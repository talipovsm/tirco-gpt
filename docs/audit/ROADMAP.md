# План развития TIRCO

Основан на находках [BUGS_AND_RISKS.md](BUGS_AND_RISKS.md), процессах [BUSINESS_LOGIC.md](BUSINESS_LOGIC.md), рекомендациях [UX_UI_RECOMMENDATIONS.md](UX_UI_RECOMMENDATIONS.md) и идеях [PRODUCT_IDEAS.md](PRODUCT_IDEAS.md). Исполнять — по [MASTER_IMPLEMENTATION_PROMPT.md](MASTER_IMPLEMENTATION_PROMPT.md).

Сроки не указаны: объём части задач зависит от решений владельца продукта (провайдер почты, правила регистрации, роли заказчика) и от того, что обнаружится на Railway. Порядок внутри этапа — рекомендуемый; этапы идут последовательно, кроме явно отмеченных параллельных задач.

## Общие правила для всех этапов

- Каждая задача — отдельная ветка и PR; один PR — одна тема.
- До PR: `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm run test:unit`, `npm run test:integration`, `npm run test:e2e` (локально, пока E2E нет в CI), `npm run build`.
- На каждую исправленную ошибку — регрессионный тест, который падает до исправления.
- Миграции — только аддитивные или с планом отката; проверка на копии production-данных до выкладки; никаких `TRUNCATE/DROP` реальных данных.
- Визуальные задачи не меняют бизнес-логику, API и права; бизнес-задачи не смешиваются с редизайном.
- Архитектурные решения — коротким ADR в `docs/adr/` (новый каталог; формат: контекст → решение → последствия).

## Почему первым идёт этап A

1. **SEC-01** — потенциальный полный доступ администратора к реальной базе на публичном стенде; проверка занимает минуты, последствия — максимальные.
2. **SEC-02** — подтверждённая утечка приватных данных груза любому перевозчику; при открытой регистрации это любой посетитель.
3. **OPS-01 и OPS-02** — без администратора и почты production-платформа не может проверять компании, разрешать споры, отменять подписанные перевозки и восстанавливать доступ пользователей: это блокирует ключевые сценарии, а не косметика.
4. Задачи этапа A небольшие и изолированные (DTO, скрипт, адаптер, лимитер, обновление зависимости) — высокий эффект при низком риске регрессий, особенно после включения E2E в CI (A1.5), которое страхует все последующие этапы.
