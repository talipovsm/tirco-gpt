# 0002. Доставка писем через SMTP

**Контекст.** Аудит (OPS-02): письма только писались в лог, поэтому в production не работали сброс пароля, приглашения по email и email-уведомления, а страница восстановления обещала письмо.

**Решение.** Драйвер `EMAIL_DRIVER=smtp` (`src/lib/notifications/email.ts`) на библиотеке `nodemailer` — SMTP поддерживает любой почтовый сервис (корпоративная почта, транзакционные провайдеры, локальный Mailpit) без привязки к одному поставщику. Отправка не блокирует ответ пользователю, ошибки пишутся в лог с маскированием адреса, две попытки. Адреса демо-домена (`*.demo`) пропускаются. Если доставка не настроена в production, страница «Восстановление пароля» честно сообщает, что ссылку получить нельзя, а сервер предупреждает при старте.

**Альтернативы.** HTTP API конкретного провайдера через `fetch` (без зависимости) — отклонено: привязывает продукт к одному поставщику; SMTP есть у всех. Собственная реализация SMTP-протокола — неоправданная сложность.

**Последствия.** Новая зависимость `nodemailer` (без транзитивных зависимостей). Для production нужно задать `SMTP_*` и `EMAIL_FROM` с доменом, у которого настроены SPF/DKIM.
